# Loodly — store assets

Everything here is generated by the scripts in `_gen/`. To regenerate the whole
kit after a copy or colour change:

```bash
cd store-assets/_gen
python3 build.py          # store icons + 288 screenshots + brand files (~100s)
python3 svg.py ../..      # re-write the in-app SVG logos
python3 appicons.py ../.. # re-write the on-device icon/splash PNGs in each app
```

The logo itself lives in `_gen/logo.py`; run it directly to preview variants
without rebuilding the kit.

Requires only Python 3 + Pillow (both already present on this machine). No
network access, no external design tool.

## Design notes

- **Palette**: brand red `#EC2828` from `mobile/constants/colors.ts`, mango
  `#FFB020` for the cone, cream `#FFF7F0` for the scoops, and a cream → warm
  blush wash as the marketing background.
- **Logo — the `oo` IS the ice cream.** Defined in `_gen/logo.py`. The `oo` pair
  of `loodly` is kerned tight (`oo_kern=-0.13`) so the two counters read as a
  scoop pair; a cream scoop cluster piles over them, and a waffle cone sits
  behind. The cone mouth is deliberately *narrower* than the `oo` span
  (`cone_width=0.42`) and pushed up behind the letters, so the cone never pokes
  out past them — the letters sit *in* the cone rather than on top of it.
  Geometry knobs: `cone_len`, `cone_width`, `cone_top`, `scoop_scale`.
- **Icon cut** (`logo_mark`) is `oo` + cone with no `l`/`dly`. Standing alone it
  carries a longer cone and fuller cloud (`cone_len=1.60`, `scoop_scale=0.92`)
  since there's no `dly` to balance against.
- **No on-red treatment.** The mark does not hold up cream-on-red — the cluster
  loses its keylines and the counters fill in — so the red tile and all cream
  inverse cuts were dropped, and the marketing backgrounds are light. Every
  surface uses the red-on-cream primary. Do not reintroduce an inverse cut
  without redrawing the cluster separation.
- Earlier concept rounds are kept in `_gen/concepts.py` and `_gen/concepts2.py`
  if the direction is ever revisited.
- **Client screens** are modelled on the real app (points card, QR, spot list,
  menu, rewards grid, map, news feed). **Courier and spot screens are mocks**
  built from the documented feature set — order queue and claim, PIN handover,
  earnings, menu availability toggles, staff shifts, reports.

## Before you submit

1. **Replace the food imagery.** `ui.photo()` draws abstract gradient blobs as
   placeholders — there is no real photography available offline. Swap in real
   product shots; the layout leaves the same boxes.
2. **Localise the two mocked apps' copy** with a native speaker if the PL
   marketing headlines will be public-facing.
3. Screenshots show a `9:41` status bar and sample data (334 points, order
   numbers, `1 248 zł` earnings) — confirm these read as plausible, and that no
   claim implies a feature that is not live.
4. The QR code in the client screenshots is a **decorative pattern**, not a
   scannable code. That is intentional, but do not present it as functional.
